# Методика оценки угроз безопасности информации (ФСТЭК, 2021)

**Статус.** Основная, обязательная методичка для построения модели угроз (Раздел 1 ВКР / практическая часть). Уже используется — модель угроз строится строго по структуре **Приложения 3**.

**Ключевые пункты, уже применённые в работе:**
- **Приложение 3** — обязательная структура модели угроз из 7 разделов: 1. Общие положения; 2. Описание систем и сетей; 3. Возможные негативные последствия; 4. Возможные объекты воздействия; 5. Источники угроз; 6. Способы реализации; 7. Актуальные угрозы.
- **п. 2.3** — допустимые источники входных данных для построения модели (а–ж), включая открытый список "и др." для баз данных векторов атак → основание для использования MITRE ATLAS и OWASP LLM Top10 в дополнение к БДУ ФСТЭК (которая слабо покрывает ИИ).
- **п. 2.7** — допускает объединение ролей (например, исследователь = пользователь в данной работе).
- **п. 2.11** — правила учёта сторонней/облачной инфраструктуры как "смежной системы" (релевантно, если LLM API — внешний провайдер, не часть системы напрямую).
- **п. 5.3.4** — угроза признаётся **актуальной**, только если для неё есть реалистичный сценарий реализации — основание для таблицы в Разделе 7.
- Формула УБИi = [нарушитель; объекты воздействия; способы реализации; негативные последствия] — используется для формулировки всех трёх угроз в Разделе 7.
- Уровни возможностей нарушителей **Н1–Н4** — используются в Разделе 5 (источники угроз: хакеры = Н2, преступные группы = Н3).

**Статус использования в ВКР:** все 7 разделов модели угроз уже написаны (черновик), осталась вычитка с научруком и, возможно, доработка Раздела 6 с явной отсылкой к абзацу про "точку потери провенанса" из Раздела 2.
