# PACT

**Что сделано.** Показывают, что policy-контроль на уровне целых действий/вызовов инструмента (action-level) слишком грубый — нарушитель может встроить вредоносные данные внутрь легитимного вызова. PACT вводит provenance-метки на уровне **аргументов** вызова (argument-level), что позволяет детерминированно проверять, откуда взят каждый кусок данных внутри запроса, до его исполнения. Заявлено 100% security (блокировка атак) на бенчмарке AgentDojo, с сохранением utility.

**Почему важно для ВКР.** Это **второй baseline** — закрывает argument-level угрозу (когда вредоносные данные проникают не через origin, а через содержимое конкретного параметра вызова инструмента/LLM). В модели угроз эта угроза тоже признаётся актуальной для необлегчённой системы, но закрывается ссылкой на PACT.

**Связь со стендом.** Нужно проверить, открыт ли код PACT. Если нет — для стенда достаточно реализовать упрощённую version argument-level проверки (минимальный чек provenance аргументов), не заявляя это как вклад ВКР.

**Важная идея для ядра работы:** механизм PACT (provenance на уровне данных, а не только origin целиком) структурно близок к тому, что нужно сделать для **памяти** агента — это полезная модель для архитектуры memory-provenance в Разделе 3/4 основного текста (не модели угроз).
