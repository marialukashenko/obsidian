# SOPGuard / SOPBench

**Что сделано.** Защитный механизм, встраивающий контроль происхождения данных (origin) в агентный браузер: данные помечаются origin'ом источника, действия, которые бы нарушили SOP (например, отправка данных с origin A на origin B), блокируются. По заявленным результатам — 0.00 violation rate на тестовых атаках, при сохранении работоспособности легитимных задач.

**Почему важно для ВКР.** Это **основной baseline** для origin-угрозы. В модели угроз (Раздел 7) этот класс угроз признаётся актуальным для неразвёрнутой системы, но закрывается ссылкой на SOPGuard как на уже существующее, измеренное решение — без переизобретения.

**Связь со стендом.** SOPGuard реализован поверх **BrowserOS** (открытый код) — выбран как базовая платформа для экспериментального стенда ВКР. План: развернуть BrowserOS + SOPGuard как есть, и **встроить поверх компонент memory-provenance** (ядро работы, см. [[Poison-Once-Exploit-Forever]]), используя тот же механизм распространения меток, что и у origin-контроля.

**Открытые вопросы:**
- Проверить точную версию/репозиторий BrowserOS с интеграцией SOPGuard (уточнить у научрука или по ссылке на project page).
- Понять формат меток origin в их реализации — чтобы расширить его на provenance памяти, а не делать параллельный механизм.
